## Обзор

Обязательно ли суммам нужны отдельные поля `SUM1`, `SUM2`, `SUM3`? Если это уже список, можно оставить их во вложенной таблице.

Так устроено демо 092. `ZCL_XTT_DEMO_092` создаёт столбцы Excel, ячейки которых читают записи из `T_SUMS` каждой строки. Шаблон - `ZXXT_DEMO_092-XLSX`.

### Сохраните фиксированный тип строки

В [демо 090](../dynamic-table/) RTTS создаёт новые поля для запрошенных столбцов. Здесь к обычным полям строки добавляется таблица сумм:

```abap
TYPES:
  BEGIN OF ts_row.
    INCLUDE TYPE ts_no_sum AS _static.
TYPES:
    t_sums TYPE tt_sums_alv,
  END OF ts_row,
  tt_row TYPE STANDARD TABLE OF ts_row WITH DEFAULT KEY.
```

`ts_no_sum` и `tt_sums_alv` определены в инфраструктуре демо. Существенна сама форма: строка со вложенной таблицей, каждая запись которой содержит `SUM`.

Метаданные столбца описаны отдельно:

```abap
TYPES:
  BEGIN OF ts_column,
    mon       TYPE numc2,
    mon_name  TYPE string,
    row_field TYPE string,
  END OF ts_column,
  tt_column TYPE STANDARD TABLE OF ts_column WITH DEFAULT KEY.
```

`ROW_FIELD` хранит выражение для последующего прохода по строкам. Пока это не сумма.

### Создайте выражение для ячейки

`GET_COLUMNS` получает названия месяцев через `MONTH_NAMES_GET` и формирует описание каждого столбца. В выражение подставляется индекс, начиная с единицы:

```abap
CONCATENATE `{R-T:v-T_SUMS[ ` lv_index ` ]-SUM;type=double}`
  INTO ls_column-row_field.
APPEND ls_column TO rt_column.
```

Для первого столбца получается:

```text
{R-T:v-T_SUMS[ 1 ]-SUM;type=double}
```

Разберём по частям:

- `R-T` задаёт контекст текущей строки.
- `v-T_SUMS[ 1 ]-SUM` читает `SUM` из первой записи вложенной таблицы.
- `;type=double` задаёт числовой результат. Выражение [`;cond=`](../cond/) по умолчанию возвращает текст, а `:` - его сокращение.

Номер месяца циклически меняется от 1 до 12, индекс таблицы продолжает расти. При более чем двенадцати столбцах исходный код повторяет названия месяцев; год автоматически не добавляется.

### Столбцы по-прежнему раньше строк

В корневой структуре `C` объявлен перед `T`:

```abap
TYPES:
  BEGIN OF ts_merge,
    c TYPE tt_column,
    t TYPE tt_row,
  END OF ts_merge.

DATA ls_merge TYPE ts_merge.
ls_merge-c = get_columns( ).

mo_report->get_random_table(
  EXPORTING iv_column_cnt = mo_report->mv_c_cnt
  IMPORTING et_table      = ls_merge-t ).

mo_report->merge_add_one( ls_merge ).
```

Шаблон разворачивает `{R-C;direction=column}` и размещает `{R-C-ROW_FIELD}` в каждом созданном столбце. Затем вставленные выражения вычисляются при повторении строк.

Корень теперь один, но порядок никуда не исчез. Если обработать строки раньше столбцов, нужных выражений ещё не будет на месте.

### Согласуйте размеры данных

В каждой строке должна быть запись суммы для каждого столбца. Третий столбец читает `T_SUMS[ 3 ]`, а не ищет сумму по бизнес-ключу или другому индексу.

Отсутствующая запись может вызвать исключение и вернуть начальное значение. Подробнее см. в разделе [обработки выражений XTT](../cond/). Сначала проверьте структуру данных: пустая ячейка сама по себе не объясняет причину.

Среда ABAP должна поддерживать табличные выражения в маркере. Если целевая система их не понимает, используйте [динамически создаваемые поля демо 090](../dynamic-table/). Повторение всей конструкции по листам показано в [демо 091](../dynamic-sheets/).
